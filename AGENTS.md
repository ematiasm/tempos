# tempos — Agent Guide

tempos is a retail and mixed-business management system for a single store, a single
warehouse and a single currency (ARS): RBAC, business settings, catalog with variants and
barcodes, customers and suppliers with current-account ledgers, unified documents (sales,
purchases, quotes, credit and debit notes, stock adjustments), stock and finance ledgers,
cash-register sessions with daily arqueo, reports, and HTML vouchers printed through
`window.print()`.

**Behaviour lives in `openspec/specs/`.** This file is the always-on index: it holds the
working rules and says which file owns each contract. If a rule here disagrees with a
spec, the spec is right and this file is wrong.

## Working rules

1. **Do not invent business data.** When a request is ambiguous or underspecified, ask
   before deciding fields, defaults, statuses, seed values, label text or anything
   domain-specific. Questions over guesses.
2. **A new SQL table gets an Alembic migration**, and the model change and the revision
   land together. Read the generated migration before applying it and remove any
   operation that does not belong to the change: an autogenerated `drop_*` left in place
   is how two database invariants went missing for eleven revisions.
3. **After any OpenAPI-shape change, regenerate the client** with
   `bash ./scripts/generate-client.sh` and confirm the frontend typecheck passes.
4. **Validation gates.** Always: backend tests, backend lint, `check-schema.sh`, frontend
   typecheck, frontend lint, frontend build. Conditional: E2E when a UI flow changed, and
   client regeneration when the API shape changed. The exact commands live in
   `openspec/config.yaml` under `testing:`.
5. **Pagination goes through `Page[T]` and `PaginationDep`.** Do not add a per-entity
   `{data, count}` schema.
6. **A new permission is added to the seed in `init_db`**, so a fresh database grants it.
   Codes follow `resource.action` (`product.create`, `sale.void`, ...).
7. **Auth dependency.** Granular endpoints use `require_permissions(...)`; superuser-only
   endpoints keep `Depends(get_current_active_superuser)`.
